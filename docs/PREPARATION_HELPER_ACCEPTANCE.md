# Проверки, приёмка и продолжение

## Реализованный MVP

`preparation.html` — три цели, ситуация, адаптивные вопросы и план. Pure модель с allowlist состояния, четырьмя ответами и источниками. Каталог: 22 вопроса, 24 правила, 18 ориентиров документов, метаданные проверки и статус проекта. `preparation-rules.html` редактирует проект формулировок и экспортирует JSON без публикации. Есть ошибки каталога, fallback копирования, повторное прохождение, сброс и очистка при уходе. Новых таблиц/RPC/ролей/миграций/Edge/npm-зависимостей нет.

## Проверка техники

Локально: 25 Node unit/сценарных тестов PASS, каталог/изоляция/CSP PASS, синтаксис JS PASS. Browser tests подготовлены для Chrome desktop и Pixel 7, включая 320/768/1280 px. Фактический CI-результат фиксируется ниже после выполнения; подготовленный тест не считается пройденным.

В managed-среде нет `$control-browser`, поэтому локальный preview server / альтернативный browser path не запускался. Browser-проверка — в изолированном GitHub Actions runner, только синтетические enum-сценарии, без Supabase, реальных аккаунтов и клиентских данных.

## Сравнение действий

Старый мастер: до 13 шагов, localStorage и собственная карточка. Новый обычный маршрут: цель → тип/оплата → 5 необязательных вопросов → план, либо сразу план после ситуации. Вход/создание/сохранение отсутствуют. Число кликов зависит от подтверждения источников и не заменяет измерение времени. Исходная обычная сводка — 1238 символов; E2E ограничивает её 3000. Сложный случай может дать больше вопросов.

## Полевая приёмка — ещё не выполнена

Новичок и опытный СПН проходят простой, ипотечный и неизвестный кейс на телефоне/компьютере без подсказок автора. Измеряются время до понятного действия, возвраты, лишние вопросы и понятность запроса юристу. Ориентир обычного случая — 2–4 минуты, пока не измеренный результат. Не собирать клиентские ФИО, суммы, адреса и документы. Дополнительной отчётности в Навигаторе нет.

## Изменение правил

1. Методист открывает редактор, выбирает правило/вопрос, меняет формулировку, версию и дату.
2. Скачивает валидный draft JSON. Изменённое правило теряет утверждение; сайт не меняется.
3. Юрист/владелец проверяет содержание и источники. Дата генерации не считается визой.
4. Уполномоченный сотрудник меняет каталог в отдельной ветке, запускает `node --test tests/unit/preparation-helper.test.mjs` и `node scripts/check-preparation-helper.mjs`, открывает PR.
5. После зелёного desktop/mobile CI и проверки diff возможен frontend-релиз. Закрытые тексты и персональные назначения в публичный каталог не копируются.

Откат: revert PR модуля/каталога. Старый v2 и его данные не изменены. Откат frontend не включает удаление production-записей.

## Backlog и решения

P0: CI, исправления замечаний, юридическая/ипотечная виза проектного содержания. P1: обезличенный пилот, сокращение вопросов, основной вход и ссылки из Помощника СПН. P2: журнал содержательных изменений, пересмотр источников, документированное CRM API discovery. Интеграция не условие полезности MVP.

Отдельный backlog v2: server-side risk gate, received/checked gate, доказуемое закрытие риска; судьба старых записей; локализация; Auth role E2E в согласованной disposable branch. Не применять DDL и не создавать legacy-задачи автоматически.

Владельцу / юристу: подтвердить содержание и ответственных за актуальность, провести пилот, затем выбрать основной вход и миграцию v2. Правила старых production RPC и migration/rollback согласуются отдельно. Модуль обозначен как пилот, без обещания правовой готовности.
